## The decisions, in order

### #13 — Do Positions need an identity?

Raised on a measured fact: **every Team in `acme-large` has a duplicated Role** (`Developer` ×3, ×4); `acme-tiny` has two by design. Storing per-shape geometry seemed to require addressing them.

**Resolved: no.** The alarm was false. Positions are not shapes — they are labels inside their Team's box, never dragged, never resized. The only thing that could have addressed one was the last layer of the style cascade, now scoped to Teams. #7's decision stood untouched, and no format change was needed.

The awkward case — "style this one seat" — turned out to really mean "style this one *person*", and Employees do have identity. That became the `occupant` cascade layer, carried to #18.

### #14 / #15 / #16 — research

- **Rendering surfaces**: shortlist Konva and React Flow, with plain SVG included only as a *baseline*. The decisive criterion was layout **ownership**, not speed.
- **Layout engines**: elkjs alone covers four of five arrangements; exact m×n grids and radial-with-real-boxes have no good off-the-shelf answer. Two contradictions surfaced: the layout graph is 100 nodes not 505, so runtime discriminates nothing; and **the example organizations are forests**, not trees.
- **Desktop shell**: Electron if a shell is built, on engine identity. But the sharpest finding was that **a shell may not be needed** — Chrome already gives native macOS dialogs and write-back.

### #17 — `title:` → `role:`

717 keys across four teams files, plus the strict schema and the README. Verified both ways: all four organizations validate, and the old spelling is now *refused* — possible only because the teams file is strict about unknown keys, so the rename cannot be half-applied and pass.

### #18 — the `.view.yaml` format

Delegated by the user, with a constraint that changed two answers: *internal to this app, free to change*.

Keyed sections rather than an ordered list (precedence belongs to the format, not to file order); encoding global but **shape a cascade property**; `occupant` layer in; one file, because after #13 only Teams carry geometry — 100 entries at worst, not 505, which made the ticket's own "geometry is the bulkiest part" premise stale.

**One thing changed rather than recorded:** the map's Notes described a single eight-layer cascade. Writing it out showed that conflates Team shapes with Position labels — different objects, different properties, no layer of one can override a layer of the other. It is **two cascades**.

### #19 — drawing surface prototype

Three spikes on one canvas. Measured at `acme-large`: all three hold 60 fps with 505 labels; first paint 28 ms (SVG) / 37 (React Flow) / 73 (Konva).

**A correction I had to issue against myself.** My first export table compared *different-sized diagrams*, because each variant had been dragged first. The controlled re-run showed all three fail silently, at different thresholds — React Flow clamps any dimension at **16384 px** and fails at 1× on real data; Konva and SVG at Chrome's **65535 px**, where `toDataURL` returns an empty `data:,`. My first comment had implied only React Flow had a defect. It understated the problem.

**Verdict: plain SVG** — the baseline, which was not on the research shortlist. It won on measurement, which means the shortlist had been drawn against a workload this project does not have.

### #20 — visual language

Sixteen renderings of `acme-medium`, published as a [contact sheet](https://claude.ai/code/artifact/e044659c-8524-4578-8bd7-a80c9620e228).

Enclosure 1.33 against node-link 7.93 on identical data. **Radial was the one casualty**: three hand-rolled angle allocations bottomed out at 10 overlapping pairs of 31 boxes, independently reproducing #15's finding.

**User kept every axis.** Consistent with the destination — a workbench that has already discarded the alternatives cannot help you find the right one. Cost: elkjs stayed in scope, justified by radial alone.

### The `fit` arrangement, found mid-stream

Not a ticket. The user reported the pain point — diagrams extremely wide or too tall — and asked for a layout that fills the window.

Three ideas, each earning its place by fixing a *measured* failure:

1. Bottom-up row packing, so a parent grows to fit its children.
2. **Enumerate the reachable wraps, don't search them** — binary search was unstable, giving 1.13 at one window size and 2.26 at another for the same target, because greedy wrapping is a step function full of local optima.
3. **Sweep one global bias**, because a parent inherits its widest child's width and per-level targeting cannot steer the whole diagram.

`acme-large`: **32.13 : 1 → 1.77** against a 1.71 window, in 4 ms. It also answered the map's open fog entry on what "heuristics" meant as an arrangement, and became the default.

### #21 — the stack

**elkjs dropped.** A fourth radial approach — relax *radially* after per-leaf angle allocation, pushing the outer box of each colliding pair further out — measured **0 overlapping pairs at 11 / 31 / 101 boxes in under 1 ms**. The dependency existed to buy one arrangement that no longer needed it.

Plain SVG, own-code layout, React, TypeScript, Vite. File System Access API, Chrome/Edge only. **No desktop shell in v1.**

Two fog entries settled in passing: the organization *is* a shape, and "circular" means `radial`.

### #22 — workbench UI

Three structurally different chromes. **Inspector rail won** — the only one with room for *provenance*, showing which cascade layer supplied each resolved property.

What the losers contributed, carried to #27: the layers rail's precedence rank and property count, and a collapsible rail.

Undo recorded as **out of v1**, with the risk named rather than hidden.

### Findings from the build

- **js-yaml rejects duplicate keys; PyYAML does not.** The hole `scripts/validate.sh` exists to plug does not exist in this app. That is luck, not design, so an assertion pins it.
- **Ajv's default entry is draft-07; the schemas are 2020-12.** Fails only at runtime — clean typecheck, clean build, broken app.
- **Vacant is not the same as unresolved.** #6 Q7 accepted that a typo and a vacancy are indistinguishable *in the file*; they need not be in the model.
- **Pan and drag-to-move compete for one gesture** (predicted in #25). Settled: shape-drag moves, empty-canvas-drag pans, **alt-drag pans anywhere** — without which `acme-large` under `fit` cannot be panned at all.
- **PNG's own limit is 2³¹−1; the canvas was always the constraint.** Rendering in tiles and assembling the PNG directly — IHDR/IDAT/IEND, CRC-32, `CompressionStream('deflate')` — removes the ceiling. Banding holds memory at 70 MB instead of 595 MB.

### A contradiction I had written into my own tickets

#27 routed the detail switches and Role filter through `arrange()`, on the reasoning that they change every box's height. **#28's done-condition required the opposite** — that hand-placed geometry survive them.

#28's rule was better. The line belongs at *what a control is about*: **placement** controls (encoding, arrangement, Arrange) discard and confirm; **content** controls (detail, filter, style) do not. #27 was amended with a comment saying so.

- **SVG export** — postponed when the drawing surface was undecided. That reason evaporated when SVG won #19; it is now the cheapest thing on the list.
- **Stale-view drift**, **reporting lines**, **semantic reorganization diff** — unchanged from the previous effort.
